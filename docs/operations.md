# 運用手順書

本番環境の面倒を見るメンテナ向けの手順です。コードを書く人向けの情報は [CONTRIBUTING.md](../CONTRIBUTING.md) にあります。

## 構成

| もの | 場所 |
|---|---|
| アプリ本体（画面・API・MCP） | Cloudflare Workers `formnow` |
| データベース | Cloudflare D1 `formnow`（APAC） |
| シークレット | Workers のシークレット（`ADMIN_TOKEN` / `MCP_TOKEN` / `GOOGLE_SERVICE_ACCOUNT_JSON`） |
| ソースコード | このリポジトリの `main` |

**正のデータはD1です。** Googleスプレッドシートは同期先にすぎず、壊れても「一括同期」で作り直せます。

## はじめてデプロイするとき（初回のみ）

```bash
npx wrangler login
npx wrangler d1 create formnow          # 出力された database_id を wrangler.jsonc に書く
npm run db:migrate:remote
npx wrangler secret put ADMIN_TOKEN     # 管理画面の合言葉。20文字以上のランダムな文字列を推奨
npx wrangler secret put MCP_TOKEN       # ClaudeからMCPで操作するときの合言葉
npm run deploy
```

シークレットが未設定のあいだは、管理APIもMCPもすべて拒否されます（401）。

## デプロイ

`main` にマージしても自動では反映されません。イベント直前に勝手に挙動が変わらないよう、意図的に手動にしています。

```bash
git switch main && git pull
npm ci
npm run check && npm test          # 念のため手元でも確認
npm run db:migrate:remote          # 新しいマイグレーションがあるときだけ
npm run deploy
```

デプロイ後に確認すること:

1. 管理画面にログインできる
2. 公開中のフォームの回答画面が開く
3. エディタの「プレビュー」で質問が正しく表示される

デプロイ直後の数十秒は、一部のURLが `error code: 1042` を返すことがあります。反映待ちなので少し待てば直ります。

### マイグレーションがあるとき

**必ず先にバックアップを取ってから** `db:migrate:remote` を実行します。マイグレーション → デプロイの順です（新しいコードが新しいテーブルを前提にするため）。

### 元に戻す（ロールバック）

```bash
npx wrangler deployments list     # 過去のバージョンを確認
npx wrangler rollback             # 1つ前に戻す
```

コードは戻せますが、**DBの変更は戻りません**。スキーマを変えたデプロイを戻すときは、バックアップからの復元が必要か検討してください。

## バックアップ

D1の中身をSQLファイルとして手元に書き出します。

```bash
npx wrangler d1 export formnow --remote --output=backup-$(date +%Y%m%d-%H%M).sql
```

取るタイミング:

- イベントの回答受付が始まる前と、終わった直後
- マイグレーションを適用する前
- チーム・回答者・質問をまとめて整理する前（削除すると紐づく回答も消えます）

バックアップには回答者の名前と回答内容が入っています。**リポジトリに入れない、共有ドライブに置くなら閲覧者を絞る。**

## シークレットの変更

```bash
npx wrangler secret put ADMIN_TOKEN
```

実行するとすぐ有効になります（再デプロイ不要）。変更すると、前のトークンでログインしていた人は入り直しになります。
管理トークンを知っている人がサークルを離れたら、変更してください。

## Googleスプレッドシート連携の初期設定（初回のみ・約15分）

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成（既存でも可）
2. 「APIとサービス」→「ライブラリ」で **Google Sheets API** を有効化
3. 「IAMと管理」→「サービスアカウント」→ サービスアカウントを作成（権限付与は不要）
4. 作成したサービスアカウントの「キー」タブ → 「鍵を追加」→ JSON をダウンロード
5. JSONの中身を1行で `GOOGLE_SERVICE_ACCOUNT_JSON` シークレットに設定
6. 連携したいスプレッドシートを、サービスアカウントのメールアドレス（`xxx@yyy.iam.gserviceaccount.com`）に**編集者として共有**
7. スプレッドシートのURLの `/d/` と `/edit` の間のIDを、フォームエディタ右上の「⚙設定」の「シートID」に貼り付け

以後、回答が送信されるたびにシートへ1行追記され、エディタの「回答」タブの「シートへ一括同期」でいつでも全回答＋集計タブを書き直せます。

## ログを見る

```bash
npx wrangler tail formnow
```

リアルタイムのログが流れます。Cloudflareのダッシュボード（Workers → formnow → Logs）でも過去分を見られます。

## イベント当日のチェックリスト

**前日まで**

- [ ] チームと回答者（審査員・メンバー・所属チーム）が全員登録されている
- [ ] 各フォームをプレビューで通して確認した（相互評価は、メンバーを選んで自チームが飛ばされることも確認）
- [ ] 計算式が意図どおりか、ダミー回答で確かめた（確かめた後のダミー回答は消す）
- [ ] スマホの実機で回答画面を開いてみた
- [ ] これ以降デプロイしない、と決めた

**当日**

- [ ] 開始前にバックアップ
- [ ] フォームを「公開中」にして、回答URLを共有（QRコードにしておくと楽）
- [ ] 受付中は、チーム・回答者・質問を**削除しない**（回答が消えます）。名前の修正は安全です
- [ ] 終了したらフォームを「締切」にする
- [ ] 終了直後にバックアップ
- [ ] 結果を発表する前に、回答数が想定人数と合っているか確認する

## 困ったとき

| 症状 | 確認すること |
|---|---|
| 管理画面に入れない（401） | トークンの打ち間違い。シークレットを変更していないか |
| 回答画面が「見つかりません」 | フォームが「下書き」のままになっていないか |
| 回答者の名前が選択肢に出ない | 役割が合っているか（審査員フォームには審査員だけ、相互評価にはメンバーだけが出ます） |
| スプレッドシートに追記されない | シートをサービスアカウントに「編集者」で共有したか。シートIDが正しいか。回答自体はD1に保存されているので、あとから「一括同期」で復旧できます |
| 順位がおかしい | 回答0件のフォームを計算式で参照しているチームは「-」になります。重みと配点上限を見直す |
